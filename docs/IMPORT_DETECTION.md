# Import v2: detect, don't ask (spec)

**Problem:** users must say which rows are headers, where data starts, and what to do with empty rows and columns; the preview lists every column, which gets long when cells hold long text. **Goal:** the app works out the layout itself, shows one line saying what it found, and asks only when unsure.

## Principles
1. Detect, then confirm: "Looks right" is one click. The existing controls (header row, question-labels row, data-starts-on) stay behind an **Adjust** link as the fallback.
2. Never change data silently: everything ignored or renamed is counted and shown.
3. Detection is a **pure function** over the first ~200 rows of the cell grid, with synthetic fixtures for every layout below and a confidence score.

## Output of detection
`{ headerRows, labelRow?, importIdRow?, dataStartRow, dataEndRow, ignoredRows[], ignoredCols[], orientation, confidence: high|medium|low, warnings[] }`
- **high:** apply and show the summary; **medium:** apply and highlight "please check"; **low:** show the compact preview and ask the user to click the header row.

## Layouts to detect
| # | Layout | How it is recognised |
|---|--------|---------------------|
| L1 | One header row, then data | header row has mostly unique short text; rows below are numeric-heavy (type shift) |
| L2 | Qualtrics export: names / question text / ImportId JSON | a row whose cells match `{"ImportId":…}`; the row above has long text; data starts after |
| L3 | Short code row + long label row | row 1 short unique codes, row 2 long text; data below |
| L4 | Two-level grouped header (group names over spans of columns) | upper row mostly blank with names repeating over spans; lower row has item names; group names kept as `column_meta.group` |
| L5 | Title/notes rows and leading blank rows or columns | rows above the table with a single filled cell; blank leading cols |
| L6 | Trailing summary rows (Mean, SD, Total, notes) | first-column labels like Mean/SD/Total/Sum, or a sudden type change at the bottom |
| L7 | Blank rows or columns inside the table | fully empty rows/cols |
| L8 | Content-validity matrix: experts across the top, items in the left column, blank rows and dimension labels (a label in the left column with the rest empty) | left column long text, other cells numeric/short codes; "dimension" rows have only the first cell filled; used by the Content-validity project type (Phase 2) |
| L9 | Transposed data (variables down the rows) | many short unique strings in column 1, numeric across; offer "transpose?" only when confident |
| L10 | SurveyMonkey-style two header rows with merged cells | top row sparse labels, second row answer options |
| L11 | Several tables in one sheet | not supported; warn and ask for the table range |

## Header scoring (v1 heuristic)
For each of the first 15 rows: non-empty fraction, text fraction, uniqueness fraction, average length; the header is the row with high text/uniqueness followed by a clear type shift (numeric-heavy rows). Data start = first row after the header block whose non-empty cells match the column profile; end = last row before a summary/notes block. Document every threshold in code constants and test them.

## Defaults and clean-up
- **Fully empty rows and columns are ignored by default**, with counts ("2 empty rows, 1 empty column ignored") and an "include them" toggle under Adjust.
- Blank header names become `Column C`; duplicates get `_2`, `_3`; shown in the summary.
- Long question text is kept as `column_meta.label` (hover/labels), never as the column name when a short code exists.
- Decimal-comma data: suggest the number format only when detected.
- Multi-sheet: detect per sheet; "apply the same layout to all sheets" only if layouts match.

## Compact preview
First 6 data rows × first 8 columns; cells truncated at 30 characters with a tooltip; horizontal scroll; "… and N more columns". Summary chips: `30 rows × 12 columns · header row 1 · 0 empty rows ignored`.

## Tests
A synthetic fixture file per layout (generated by a script, no real data) with the expected detection JSON; ambiguous files must return **low** confidence rather than guess; round-trip: detected layout → parsed grid equals the expected grid.
