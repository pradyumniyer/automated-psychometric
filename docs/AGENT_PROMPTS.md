# Agent prompts (copy one at a time into a NEW agent chat: Codex or Copilot Agent)

Rules: one prompt per chat unless noted; paste the agent's final report to Claude for review before moving on; push only after approval (agents never push). The standing rules live in `.github/copilot-instructions.md` (and `docs/PROJECT_RULES.md`); every prompt points to that file, which works for Copilot and for Codex. Prompts may be refined after a review. Before each run, check `git status --short` prints nothing so the report's `git diff --stat` shows only the agent's work. Prompts that have already been run are kept in `docs/archive/AGENT_PROMPTS_DONE.md` (history only).

## How to run a prompt (one branch per prompt)
1. `git status --short` must print nothing. Then: `git switch local-first-rebuild`, `git pull`, `git switch -c <short-name>` (for example `p2c4-words`).
2. Open a NEW chat in the agent you are using, paste only the code block of the prompt, send. Do not use two agents on the folder at the same time. If the agent runs out of allowance mid-way, start a new chat on the same branch and paste: "Continue the previous prompt from the last commit; read `git log` and the remaining items below" plus the unfinished part of the prompt.
3. When it stops: `git status --short` (should print nothing) and `git log --oneline -6`; paste the report to Claude. Push the branch (`git push -u origin <short-name>`, temporary) only when Claude asks to read the code (the repo must be public at that moment); delete it afterwards with `git push origin --delete <short-name>`.
4. After approval and your hand test: `git switch local-first-rebuild`, `git merge --ff-only <short-name>`, `git push`, `git branch -d <short-name>`. If the merge refuses, stop and show Claude.
5. If the work is rejected: `git switch local-first-rebuild`, `git branch -D <short-name>` (this discards everything the agent did on that branch).
6. If `git status --short` shows uncommitted changes after the agent stops, do not switch branches; show Claude the output.

## Standing test rules for every UI prompt (also in `.github/copilot-instructions.md`)
1. Behaviour that the user can see is tested on the REAL screen: mount `ConfigScreen` (or the real screen concerned) in jsdom with `fake-indexeddb` and drive it with user-event; never a test-local wrapper that re-implements handlers. Recipe: `tests/responseScaleRealScreen.test.ts` (shared helper `tests/helpers/realScreen.ts`). Vitest only runs `tests/**/*.test.ts`, so use `React.createElement`. Scoring is a manual step (rail step "Scoring", button "Run Scoring"); autosave runs 1 second after the last change (flush before reloading).
2. Every control that a prompt adds or touches is exercised by clicking or typing in at least one test: links, buttons, dropdowns, inputs. A control that does nothing is a bug.
3. Every scenario also runs: fresh upload, after reload (unmount and mount again), and the template-applied path.
4. Expected numbers come from an independent reference (python or a tiny scorer in the test that reads the raw CSV), never from the app.
5. Generality: no fixture value, column name, respondent id or subscale name in non-test source; synthetic datasets for edge cases are built inside tests.
6. "Displayed = saved = scored": what a card shows must be what scoring uses after a reload.
7. Report format: commits; for each requirement passed, failed or "visual only, not verified"; the failing output from before the fix for the main reproductions; test counts and run times; lint totals (baseline 3 errors, 3 warnings, no new findings); "Proven by automated tests" and "Not checked in a browser" lists; behaviour that differs from the docs.
