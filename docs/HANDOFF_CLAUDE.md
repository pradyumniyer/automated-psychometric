## State model for a subscale's response scale (built; see RESPONSE_SCALES 16)
`minValue/maxValue` = effective range (everything downstream reads only these); `rangeSource` detected|manual|preset; `baseMin/baseMax`; `outOfRangeDecisions[valueText] = {action: missing|widen, reviewed}`; typed numbers live in `labelMap`; effective range = base widened by widened values; detection seeds the base only while source is detected and only when dataset or items change; typing a range -> manual and clears widen decisions; confirmation (reverse-item subscales only) resets only on a real change. P2c-4 adds `labelSource` (detected|preset|manual) and word seeding (RESPONSE_SCALES 17).

## How to review an agent report (lessons from this project)
- Check scope against the prompt; full test, typecheck, build; lint totals before and after (no new findings); compare the report's claims with his screenshots; read the "Not checked in a browser" list.
- Tests must mount the REAL screen over fake-indexeddb with user-event; a test-local wrapper that copies the handlers hid the effect bug for several rounds. Check which component the tests mount before believing "863 tests pass".
- Expected numbers must be computed outside the app (python from the raw CSV).
- For UI work give a layout or mockup, not only prose; this model misreads loose specs. Every prompt carries the generality rule, the expected numbers, separate commits, and "stop for review".
- When a hand test fails, reproduce on the real screen yourself before writing the fix prompt, find the cause (switch suspect code off to prove it), and look for the same pattern elsewhere (the effect bug, the stale double update, displayed-not-saved values).
- Prompts must say what to do when the agent runs out of allowance (continue from the last commit).
